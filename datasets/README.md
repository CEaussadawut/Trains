# Bangkok Transit Dataset

โครงข่ายรถไฟฟ้ากรุงเทพฯ — สายที่เปิดให้บริการแล้ว + สายที่ยังสร้างไม่เสร็จ (พร้อมข้อมูลประมาณการ)

```
21 สาย   302 สถานี   289 edges   42 จุดเชื่อมต่อ   7 operator

operating           11 สาย   (BTS เขียว/ทอง, MRT น้ำเงิน/ม่วง/เหลือง/ชมพู, SRT แดง, ARL)
under_construction   3 สาย   (ส้มตะวันออก, ส้มตะวันตก, ม่วงใต้)
planned              7 สาย   (น้ำตาล, เทา, เงิน, ฟ้า, ส่วนต่อขยายสายสีแดง 3 เส้น)
```

ทุกตารางมีคอลัมน์ `is_estimated` — `1` = แถวนี้มีค่าประมาณอยู่ กรองด้วยคอลัมน์นี้ได้ตลอด

| ตาราง | แถว | ประมาณการ |
|---|---|---|
| `lines.csv` | 21 | 10 (48%) |
| `stations.csv` | 302 | 108 (36%) |
| `edges.csv` | 289 | 220 (76%) |
| `transfers.csv` | 42 | 21 (50%) |

## lines.csv

| คอลัมน์ | คำอธิบาย |
|---|---|
| `line_id` | รหัสสายที่ใช้อ้างอิงในตารางอื่น |
| `name_th`, `name_en` | ชื่อสาย |
| `color` | สีประจำสาย |
| `operator` | ผู้เดินรถ — `BTSC` `BEM` `EBM` `NBM` `SRTET` `AERA1` `MRTA` **ใช้ตัดสินว่าเสียค่าแรกเข้าใหม่หรือไม่** |
| `owner` | เจ้าของโครงการ — `BMA` `MRTA` `SRT` |
| `status` | `operating` / `under_construction` / `planned` **ใช้เป็นสวิตช์ scenario** |
| `mmap2_tier` | `A1` / `A2` / `B` ตามการจัดลำดับใน M-MAP 2 (ว่างสำหรับสายที่เปิดแล้ว) |
| `mode` | `elevated` `underground` `monorail` `heavy_rail` `apm` `lrt` |
| `num_stations` | จำนวนสถานีบนสาย |
| `est_opening_year` | ปีที่เปิด (สายที่เปิดแล้ว) หรือปีที่คาดว่าจะเปิด (ค่าประมาณ) |
| `avg_speed_kmh`, `dwell_sec` | พารามิเตอร์ที่ใช้คำนวณ `travel_sec` |
| `is_estimated` | `1` ถ้ายังไม่เปิดให้บริการ |

## stations.csv

| คอลัมน์ | คำอธิบาย |
|---|---|
| `station_id` | รหัสสถานี (`N8`, `BL21`, `PK16`, `A6`, `OR12` ...) |
| `name_th`, `name_en` | ชื่อสถานี |
| `lat`, `lon` | พิกัด |
| `lines` | สายที่ผ่านสถานีนี้ คั่นด้วย `\|` — สถานีหนึ่งอยู่ได้หลายสาย (เช่น `CEN` = สยาม) |
| `coord_source` | `anchor` = พิกัดจริงโดยประมาณ (147 สถานี) / `interpolated` = เติมเชิงเส้นระหว่าง anchor (155 สถานี) |
| `is_estimated` | `1` ถ้าสถานีอยู่เฉพาะบนสายที่ยังไม่เปิด |
| `map_x`, `map_y` | **ตำแหน่งคงที่บนผังแผนที่** (px) — ไม่ใช่พิกัดภูมิศาสตร์ ดูหัวข้อผังด้านล่าง |
| `label_side` | `left` / `right` — ควรวางป้ายชื่อไว้ข้างไหนของสถานี |

## edges.csv

ช่วงรางระหว่างสองสถานีที่ติดกัน — **ไม่มีทิศทาง** ให้ถือเป็นสองทาง

| คอลัมน์ | คำอธิบาย |
|---|---|
| `from_id`, `to_id`, `line_id` | สถานีต้นทาง-ปลายทาง และสายที่วิ่ง |
| `dist_m` | ระยะทางเส้นตรง (haversine) ระหว่างพิกัดสองสถานี |
| `travel_sec` | `dist_m / avg_speed_kmh + dwell_sec` |
| `is_estimated` | `1` ถ้าสายยังไม่เปิด หรือปลายทั้งสองด้านไม่ใช่ anchor |

## transfers.csv

การเปลี่ยนสาย — **ไม่มีทิศทาง** เช่นกัน `from_id` เท่ากับ `to_id` ได้ (เปลี่ยนสายในสถานีเดียว)

| `transfer_type` | ความหมาย | เสียค่าแรกเข้าใหม่ |
|---|---|---|
| `PAID` | เขตชำระเงินเดียวกัน (สยาม, เตาปูน, บางซื่อ) | ไม่ |
| `PAID_MULTI` | สถานีเดียวคนละชั้น เขตชำระเงินร่วม | ไม่ |
| `SKYWALK` | เดินเชื่อมด้วยทางเดินลอยฟ้า ต้องแตะออก-เข้า | ใช่ |
| `EXIT` | ต้องออกจากระบบแล้วเข้าใหม่ | ใช่ |

คอลัมน์ `exit_required` (`0`/`1`) สรุปข้อมูลเดียวกันในรูปที่ใช้ในโค้ดได้ทันที

**สถานีเดียวกันที่มีหลายสายแต่ไม่ปรากฏในไฟล์นี้** ให้ถือว่าเปลี่ยนสายได้ในเขตชำระเงินเดียวกัน
(เช่น `PP16` เตาปูน ที่เป็นทั้งม่วงเหนือและม่วงใต้)

## fares.csv

| คอลัมน์ | คำอธิบาย |
|---|---|
| `operator` | ตรงกับ `operator` ใน lines.csv |
| `base_fare` | ค่าโดยสารเริ่มต้นเมื่อเข้าระบบ |
| `per_station` | ค่าโดยสารเพิ่มต่อสถานี |
| `max_fare` | เพดานค่าโดยสารต่อการเดินทางหนึ่งครั้งในระบบนั้น |
| `entry_fee` | ค่าแรกเข้าเมื่อเปลี่ยนเข้ามาจาก operator อื่น |

สูตร: `min(base_fare + per_station × จำนวนสถานี, max_fare)` ต่อ operator
แล้วบวก `entry_fee` ทุกครั้งที่เข้าระบบใหม่

## ผังแผนที่ (`map_x` / `map_y`)

ตำแหน่งคงที่แบบแผนที่รถไฟฟ้าจริง — บิดเบือนระยะทางได้ แต่รักษาทิศทางคร่าวๆ
และโครงสร้างการเชื่อมต่อไว้ครบ คำนวณด้วย `build_layout.py`

```
ช่วงรางที่เป็นมุม 45°/90°   99%
ความยาวช่วงราง             42 ± 12 px
สถานีทับกัน                0
ขนาดผัง                    1097 x 1518 px
```

- **ไม่มีการสุ่ม** — รันกี่ครั้งก็ได้ผังเดิมทุกครั้ง (ตรวจด้วย md5 แล้ว)
- **คำนวณบนโครงข่ายเต็มแผนครั้งเดียว** — สลับ scenario แล้วสถานีไม่ขยับ
- เริ่มจากการฉายพิกัดภูมิศาสตร์จริง ผังที่ได้จึงยังพอเดาทิศได้ (เหนืออยู่บน ตะวันออกอยู่ขวา)
- `origin` อยู่มุมซ้ายบน แกน `y` ชี้ลงตามระบบพิกัดของ SVG

อยากได้ผังหน้าตาอื่นก็แก้ค่าคงที่หัวไฟล์ `build_layout.py` (`MIN_LEN`, `MAX_LEN`,
`MIN_SEP`, `XFER_LEN`) แล้วรันใหม่

## เครื่องมือที่ให้มาด้วย

| ไฟล์ | หน้าที่ |
|---|---|
| `build_layout.py` | คำนวณผังคงที่ เขียนกลับลง `stations.csv` |
| `build_viewer.py` | ฝังข้อมูล + ผัง ลงใน `graph_viewer.html` |
| `graph_viewer.html` | แผนที่แบบโต้ตอบได้ เปิดด้วยเบราว์เซอร์ ไม่ต้องมีเซิร์ฟเวอร์ |
| `render_preview.py` | วาดแผนที่ออกเป็น SVG / PNG โดยไม่ต้องเปิดเบราว์เซอร์ |
| `preview/` | ภาพผังของทั้งสาม scenario |

## วิธีประมาณข้อมูลของสายที่ยังสร้างไม่เสร็จ

**สิ่งที่อ้างอิงของจริง**

- ต้นทาง-ปลายทางของแต่ละสาย และแนวเส้นทางคร่าวๆ
- สายไหนเป็นของ operator ใด (กำหนดว่าจะเสียค่าแรกเข้าใหม่ตรงไหน)
- จุดเชื่อมต่อกับสายที่เปิดแล้ว — เช่น สายสีส้มเชื่อมน้ำเงินที่ศูนย์วัฒนธรรมฯ และบางขุนนนท์, เชื่อมชมพูที่มีนบุรี, เชื่อมเหลืองที่ลำสาลี
- การจัดลำดับ A1 / A2 / B ตาม M-MAP 2

**สิ่งที่เป็นค่าประมาณ**

- **ชื่อสถานีบางส่วน** — ชื่อสถานีปลายทางและจุดเชื่อมต่อใช้ชื่อจริง สถานีระหว่างทางบางแห่งตั้งตามชื่อถนน/ย่านที่เส้นทางผ่าน
- **พิกัดทั้งหมด** — วางสถานีโดย interpolate เชิงเส้นระหว่างจุดปลายและจุดเชื่อมต่อที่รู้พิกัดจริง
- **ระยะระหว่างสถานี** — เป็นผลพลอยได้จากการ interpolate ไม่ใช่ระยะออกแบบจริง
- **เวลาเดินทาง** — คำนวณจากความเร็วเฉลี่ยตาม `mode` โดยใช้ค่าเดียวกับสายที่เปิดแล้วซึ่งเป็น mode เดียวกัน (monorail 30 km/h, ยกระดับ/ใต้ดิน 35 km/h, heavy rail 45 km/h) + dwell 25–35 วินาที
- **ค่าโดยสาร** — ใช้สูตรของ operator ที่เป็นเจ้าของสายนั้นตาม M-MAP 2
- **เวลาเดินเปลี่ยนสาย** — 180 วินาทีสำหรับเปลี่ยนในเขตชำระเงินเดียวกัน, 240–300 วินาทีเมื่อต้องออก-เข้าใหม่
- **ปีที่เปิด** — เรียงลำดับตาม tier ของ M-MAP 2 ใช้จัด scenario เท่านั้น ไม่ใช่การพยากรณ์

## ข้อควรทราบ

1. **โครงสร้างแม่น ตัวเลขประมาณ** — ลำดับสถานี จุดเชื่อมต่อ และเจ้าของสาย ตรงกับของจริง ส่วนพิกัด ระยะทาง และเวลา เป็นค่าประมาณ
2. **พิกัดของสายที่เปิดแล้วก็ยังคลาดเคลื่อนได้** — 147 สถานีเป็น anchor (ระดับหลักร้อยเมตร) อีก 155 สถานี interpolate ดึงพิกัดจริงเพิ่มได้จาก OpenStreetMap โดยจับคู่ด้วย `station_id` กับ tag `ref`
3. **ไม่มีมิติเวลา** — ไม่มี headway, เที่ยวแรก-เที่ยวสุดท้าย, ช่วง peak/off-peak
4. **`max_fare` ทำให้ค่าโดยสารไม่เป็น additive** — ถ้าใช้ค่าโดยสารเป็นส่วนหนึ่งของ cost ใน A\* ควรละเพดานไว้ระหว่างค้นหาแล้วคำนวณค่าจริงทีหลัง มิฉะนั้น heuristic จะไม่ admissible
5. **ท่าพระถูกยุบเป็น node เดียว (`BL01`)** แม้ของจริงมีสองรหัส เพราะเป็นสถานีเดียวกันในเชิงกราฟ — สายสีน้ำเงินจึงปิดวงที่ `BL32 → BL01` และแตกสาขาที่ `BL01 → BL34`
6. **รหัสสถานีสาขาหลักสอง (`BL34`–`BL39`) อาจไม่ตรงกับรหัสทางการ** ลำดับสถานีถูกต้อง แต่ควรตรวจกับเว็บ BEM ก่อนอ้างรหัสในเอกสาร
